# 中央氣象署 SWOO 架構分析與介接記錄

> 分析日期：2026-08-18。對象：[中央氣象署太空天氣作業辦公室](https://swoo.cwa.gov.tw/V2/)（SWOO）。
>
> 標「已驗證」者為**實際發出請求確認**，非由網頁文字推斷。

## 為什麼要分析它

SWOO 在本專案文件中反覆出現，身分有二：本專案「不取代」的定位對象，
以及架構書列為 C 級「需機關協調」的資料源。實際盤查後，兩件事都需要修正認知。

---

## 一、SWOO 的架構

58 個頁面、6 個區塊，骨架是 **觀測 → 監測 → 預報** 的三層流水線：

| 區塊 | 頁數 | 內容 |
|---|---|---|
| 觀測資料 | 15 | 太陽影像、日冕儀、GOES X 射線／粒子、太陽風、黑子、**電離層探測儀**、**磁力計**、**TEC 圖**、掩星產品、福衛七號 IVM／RFI／scnGeo |
| 監測數據 | 4 | 全球擾動指數（Dst／Kp／Hpo）、**臺灣地磁擾動**、**GNSS 閃爍**、即時尺度 |
| 預報產品 | 7 | 綜合預報、電離層預報、**閃爍預報**、極光 OVATION、無線電吸收、磁層頂、WSA-Enlil |
| 太空天氣 | 5 | 概論、歷史事件、影響範圍、尺度說明 |
| 科教新知 | 18 | 儀器說明、FAQ、影片 |
| 便民服務 | 3 | 字典、下載、連結 |

這個分層與本專案的 擷取層 → 模型層 → 預報層 幾乎同構。

### 它有而本專案沒有的：在地實測

- **逾 100 個地面 GNSS 測站**（地震測報中心維運）的 S4 閃爍指數
- **三分量磁力計**（同一單位維運）
- 電離層探測儀、無線電信標
- 福衛七號掩星產品（ionPrf、podTec、scnGeo）
- 72 小時逐時的**閃爍預報**（中央大學經驗模式，基於福衛三號歷史觀測，門檻 0.2／0.5／0.8）

### 它沒有而本專案在做的：任務化轉譯

SWOO 的尺度頁確認：**直接採用 NOAA G/R/S，沒有自訂分級**。它有環境強度，但沒有：

- 任務風險等級與對應的處置／通報對象
- 「沒資料」與「沒事」的機器可讀區分
- 推估與實測的欄位級標示
- 雙時間軸與無前視偏差回放
- 事件卡狀態機與稽核軌跡
- 驗證擂台與技巧分數

**兩者互補而非重疊**，這印證了架構書「不重建國家級預報中心，而是建立任務化轉譯層」的定位。

### 一個獨立印證

SWOO 在尺度頁自行註明：**臺灣地磁緯度較低，實際影響與美國預測不同**。
這與本專案 `docs/glossary.md`「臺灣地磁緯度僅約 19°N、不可用地理緯度判斷」
是同一件事的兩個獨立來源。

## 二、資料取得

### 端點清單〔已驗證〕

前端 `/V2/js/SWDataLoad.js` 顯示資料由六個 JSON 端點供應，皆無需認證：

| 端點 | 內容 | 實測更新時間 |
|---|---|---|
| `/json/SWInfo.json` | 綜合現況（含 **TWTEC**、**TWDI**）、G/R/S、中英雙語預報全文 | 約一日 |
| `/json/get_web_5min.json` | Dst、Kp、IMF、太陽風、X 射線、質子、電子通量 | 即時 |
| `/json/get_web_3hr.json` | ap、Kp、F10.7、黑子數 | 即時 |
| `/json/get_web_day.json` | 三日 F10.7 與地磁／閃焰機率展望 | **停滯數月** |
| `/json/SWForecast.json` | 預報文字與 G/R/S | 約一日 |
| `/V2/json/SWxScale.json` | 尺度摘要 | **停滯數月** |

**新鮮度極不一致**：即時通道活著，但日尺度預報與尺度摘要已停滯數月。
若介接，`latency_budget_s` 必須**逐端點**設定，否則會把停滯值當現況。

### 本專案實際取用的欄位

只取**在地獨有**的兩個量。同一端點另含 `kidx`／`DST`／`sws`／`XrayFx` 等全球量，
本專案已有權威來源（GFZ、京都、SWPC、CelesTrak），重複入庫只會製造
同一時刻多來源的取捨負擔而無新資訊。

| SWOO 欄位 | 本專案參數 | 定義 |
|---|---|---|
| `TWTEC` | `TEC`（TECU） | 地面 GNSS 接收網反演，投影至 300 km |
| `TWDI` | `DB_TW`（nT） | 三分量磁力計水平總強度減寧靜基線，各站取**中位數** |

## 三、授權

**這些端點是 SWOO 網站前端自用，不是公開發布的 API**，站上並載明
「非經授權禁止轉載使用」。

本案**經成功大學合作管道向中央氣象署取得授權後使用**。
授權依據記於 `configs/sources.yaml` 的 `attribution.terms` 欄位，
並有契約測試（`tests/test_contracts.py::test_restricted_source_terms_are_explicit`）
確保該限制寫在條款而非僅存於註解。

> **第三方不得比照辦理。** 複用本專案者若要啟用 `cwa_swoo` 來源，
> 須自行向中央氣象署取得授權。

原始 JSON 一律不進版控（`.gitignore` 已涵蓋 `data/raw/cwa_swoo/`），
把授權受限的原始資料放進公開 repo 等同代為散布。

## 四、待確認事項

### TWDI 的基線定義〔阻擋項〕

抓取當下的數值不自洽：

| 量 | 值 | 判讀 |
|---|---|---|
| `TWDI` | **−186.42 nT** | 在 SWOO 自己的圖軸（−500～+100）上屬暴時量級 |
| `DST` | −28 nT | 平靜 |
| `kidx` | 3.67 | 平靜 |

低緯地區的 Sq 日變化可達數十 nT，但 −186 與平靜的全球指數仍不相稱。
可能成因：基線未完全扣除日變化、基線漂移、或該欄位停滯。

**在與 CWA 確認基線定義與時間解析度之前，`DB_TW` 不驅動任何分級規則**
（`configs/rules/` 未引用該參數）。直接接上會產生誤警。

### 待向 CWA 確認的問題

1. `TWDI` 的基線如何定義？是否已扣除 Sq 日變化？更新頻率為何？
2. `TWTEC` 是單一代表值或格網平均？取樣的空間範圍為何？
3. `get_web_day.json` 與 `SWxScale.json` 的停滯是暫時或已停止維護？
4. 是否可能提供正式的資料介接管道（含服務等級與變更通知）？
5. `scnLv1`（S4）是否可透過此途徑取得？

## 五、技術註記：TLS

CWA 的憑證由 TAIWAN-CA 簽發，其中介憑證**缺少 Subject Key Identifier 擴充**。
Python 3.12 起預設開啟 `VERIFY_X509_STRICT`，會因此拒絕連線
（curl 與瀏覽器可通）。

本專案的處理方式是**逐來源明示啟用**的旗標：

```yaml
tls_relaxed_strict: true
```

**這不是關閉憑證驗證**——憑證鏈仍對 CA 信任庫完整驗證、主機名仍比對，
唯一放寬的是 RFC 5280 對憑證擴充欄位的嚴格一致性檢查。
刻意不做成全域預設：全域關閉會讓未來任何一個真正有問題的憑證安靜通過。

實作見 `services/ingest/base.py` 的 `_RelaxedStrictAdapter`。
