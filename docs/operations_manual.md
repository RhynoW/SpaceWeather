# 正在發生

## 30 秒定位

開啟儀表板，預設落地頁就是**值勤模式**。
先看最上排三個網域燈號，再看右側資料齡期。這兩件事決定你接下來要不要動作。

**三個必記**

1. **灰色 ≠ 綠色**——沒資料不是沒事。
2. **模型 ≠ 實測**——標 `proxy` 的結論不可對外表述為實測。
3. **24 小時以上的預報不能拿來做決策。**

**時間全部是 UTC**，臺灣時間 = UTC + 8。交班紀錄請一律用 UTC，避免跨日誤讀。

**等級有兩套**：`mission_level`（L0–L4，本系統自訂）與 `international_scale`
（G/R/S，NOAA 定義）是兩個獨立欄位，**不能互相換算**。

> ### ⛔ 最容易犯的錯
>
> **把「沒資料」當成「沒事」。**
> 規則回報 `unavailable` 代表判定所需的資料源不存在，**不代表風險為零**。
> 儀表板對此顯示灰色而非綠燈，就是為了防這個誤讀。
> 看到灰色時，正確反應是**去查那個通道為什麼沒有資料**，不是放心。

## 燈號與等級

任務風險等級 `mission_level` 是本系統自訂的五階，門檻寫在 `configs/rules/*.yaml`。
**目前標記為 `calibrated: false`**——尚未與需求單位校準，等級的絕對意義仍待定版。

| 等級 | 名稱 | 意義 |
|---|---|---|
| —（灰） | **無資料** | 判定所需資料不存在。**不是安全。** |
| **L0** | 正常 | 規則未觸發，**且該網域有資料** |
| **L1** | 注意 | 環境轉變，納入任務前提示 |
| **L2** | 警戒 | 影響可量測，需通報相關席位 |
| **L3** | 嚴重 | 建議調整任務規劃。**須人工確認後發布** |
| **L4** | 重大 | 啟動重大事件通報與事件復盤 |

### NOAA 國際尺度

G/R/S 描述的是**環境事件有多強**，L0–L4 描述的是**對我方任務有多大影響**。
同一場 G4 對地面單位可能只是 L1，對低軌操作單位可能是 L4，所以系統不提供換算表。

| 級 | G　地磁暴（依 Kp） | R　無線電衰減（GOES 0.1–0.8 nm） | S　輻射風暴（≥10 MeV 質子） |
|---|---|---|---|
| 1 | Kp 5 | 1×10⁻⁵（M1） | 10 pfu |
| 2 | Kp 6 | 5×10⁻⁵（M5） | 10² pfu |
| 3 | Kp 7 | 1×10⁻⁴（X1） | 10³ pfu |
| 4 | Kp 8 | 1×10⁻³（X10） | 10⁴ pfu |
| 5 | Kp 9 | 2×10⁻³（X20） | 10⁵ pfu |

### 判定依據 `inference`

事件卡的每個影響分項都帶此欄位，**永遠不會是 `null`**。
這是判斷「這個結論有多硬」的關鍵——四個值意義完全不同：

| 值 | 意義 | 值勤時怎麼看 |
|---|---|---|
| `observed` | 直接觀測值判定 | 可作為判斷依據 |
| `modelled` | 模型或預報輸出，非當下觀測 | 可參考，但須註明來源為模型 |
| `proxy` | 由其他量間接推估 | **不可對外表述為實測** |
| `unavailable` | 判定所需資料不存在 | **不是安全**，須查通道狀態 |

> **收到 `null` 時**：若任何介面回傳 `null` 或缺少 `inference` 欄位，
> **不得自動解讀為 `observed`**——那是舊版行為或介接錯誤，請回報系統管理員。
>
> 網域層級的 `inference` 取該網域內**最弱**的一項：
> 只要有任一分項是推估，整個網域就不能宣稱為觀測所得。

> **KP 組是代理，DRAG 組是實測。** 上表四條以 Kp/Ap 為門檻——地磁擾動強
> 不等於熱氣層密度一定高，只是相關。下表四條取自福衛七號精密定軌反演的
> 密度增強倍數 `DRAG_ENHANCEMENT`（觀測衰減率 ÷ 同一 F10.7 之寧靜期望值）。
>
> 實測 2024-04-29 至 05-20 顯示**密度響應對 Kp 高度非線性**：
> Kp 6–7 的增強中位僅 **1.19**，Kp ≥ 7 才達 **2.34**。該窗內 KP 組觸發 15 次、
> DRAG 組僅 4 次且全在 Gannon——**Kp 代理在中等擾動時明顯過度告警**。
>
> **但 DRAG 組是尾隨量**（標在 t 的值描述 t−6h 到 t），不適合當暴起始指標。
> 兩組並用：KP 給前導訊號，DRAG 給已發生的量值。
> 無 leoOrb 資料時 DRAG 組回報 `unavailable`，網域落在 `partial`——
> 手上只有代理、無法確認，這正是要呈現的狀態。

### 衛星定位　`GNSS_PNT`

> ⚠️ **此網域部分為推估。**
> S4 已有實測來源（福衛七號掩星閃爍 `scn1c2`），TEC 亦有；但 **ROTI 仍無來源**，
> 故 L3 那條在只有 S4 時回報 `partial` 而非 `ok`——
> 已有的判據若超標仍會發報，但「沒有告警」不等於已確認平靜。
> 標 `proxy` 的兩條規則仍是**間接推估**。
>
> **掩星 S4 與地面站 S4 不是同一種量**：前者取自臨邊射線切點附近，
> 後者是測站正上方的垂直觀測，取樣體積與代表性都不同，門檻不可互用。

| 等級 | 觸發 | 依據 | 影響 | 處置 |
|---|---|---|---|---|
| **L1** | `Kp ≥ 5` | `proxy` | 電離層不規則體機率上升，定位精度可能劣化（**無在地實測佐證**） | 高精度 PNT 作業預留額外誤差；留意授時穩定度 |
| **L2** | `TEC ≥ 80`<br>持續 0.5 h | `observed` | 單頻定位電離層延遲誤差顯著增加 | 單頻接收改用雙頻或加大誤差預算 |
| **L2** | X 射線 `≥ 1×10⁻⁴` | `proxy` | 閃焰造成 TEC 突增（SITEC），單頻定位誤差短時上升；日照側為主 | 延後高精度單頻定位作業 |
| **L3** | `S4 ≥ 0.6`<br>或 `ROTI ≥ 0.8`<br>持續 0.25 h | `observed` | 定位精度劣化、載波失鎖風險升高；授時同步可能中斷 | 改用多頻多系統接收、延後高精度作業、啟用慣性／守時備援 |

## 收到告警怎麼做

以下為 **L3 或 L4** 出現時的處理次序。這是真實的先後序列，請依序執行。

1. **確認等級與依據。**
   開啟值勤模式，讀事件卡的 `mission_level`、`international_scale`
   與各影響分項的 `inference`。若關鍵分項是 `proxy`，對外表述時必須說明「為推估」。

2. **檢查資料是否可信。**
   看右側資料齡期。若驅動該告警的通道顯示紅色或無資料，先排除資料異常再通報——
   **用過期資料發告警比不發更傷信任。**

3. **依處置對照表執行。**
   見上一節，按網域與等級取「處置」與「通報」欄。

4. **人工確認後發布。**
   L3 以上的事件卡建立時狀態為 `draft`，須經人工確認轉為 `issued`。
   發布者會記入稽核軌跡。**未經確認的事件卡不得對外發送。**

5. **持續追蹤修訂。**
   事件卡內容變動會產生新的 `revision`，前版標為 `superseded`。
   以最新修訂為準，並注意等級可能升降。

6. **事後復盤。**
   L4 須做事件復盤。可用回放功能重現「當時已知什麼」——見 [產品匯出](#產品匯出) 的 `--as-of`。

> ### 為什麼要回放
>
> 復盤時若直接用今天的資料看當時，會用到**事後才訂正的數值**，
> 得出「當時明明看得出來」的錯誤結論。
>
> 系統以雙時間軸記錄（`valid_time` 物理時間、`ingest_time` 入庫時間），
> `--as-of` 只回傳該時刻**已經入庫**的資料。
>
> 實例：回放到 Gannon 事件起始時刻，系統只知道 Ap=105，因此發出 **L3/G3**，
> 而不是事後才確定的 L4/G4。

# 例行值勤

## 值勤模式頁

預設落地頁，設計目標是**事件發生時 10 秒內掌握全局**，不必逐頁切換。四個區塊：

| 位置 | 內容 |
|---|---|
| **上排**　三網域燈號 | 軌道預報／短波通信／衛星定位。顯示等級、觸發中的規則、判定依據註記。無資料時是**灰色方塊**，不是綠燈 |
| **左下**　最近事件 | 近 7 日事件卡，含狀態徽章（待人工確認／已發布／已被取代）、持續時數、可信度，以及間接推估分項的數量警示 |
| **右上**　資料齡期 | 六條關鍵通道的新鮮度。紅色代表超出該參數更新週期的五倍，白色圓圈代表完全沒有資料 |
| **右下**　關鍵指標 | Kp、Dst、Bz、太陽風速度、X 射線的現值與判讀區間。**此處的區間是教學參考，不是系統告警門檻** |

> **這頁刻意不顯示什麼**
>
> **24 小時以上的預報不會出現在值勤模式。**
> 該預報測試折的 BSS 於 24 小時起轉負（不優於「永遠報氣候頻率」），
> 放在值勤頁只會誘導誤用。需要查看時請到「48 小時預報」頁，該頁有紅色警示。

## 判讀資料狀態

系統把「沒事」與「沒資料」嚴格分開。四種狀態要分清楚：

| 狀態 | 意義 | 在哪看到 | 正確反應 |
|---|---|---|---|
| **L0** | 規則未觸發，**且該網域有資料** | 燈號綠色 | 正常值勤 |
| **`unavailable`** | 判定所需資料不存在 | 燈號灰色；`/v1/rules` 的 `status` | **查通道為何無資料**，不可視為安全 |
| **`degraded`** | 來源可取得，但資料齡期超出該參數更新週期 | 資料健康頁；`/v1/obs` 的 `degraded` | 資料仍可用但已不新鮮，判讀時降低權重 |
| **DEMO** | 使用示範快照，非即時作業資料 | 頁面頂端黃色橫幅；`/health` 的 `data.is_demo` | **不得據以做任何作業判斷** |

> ### DEMO 橫幅為何重要
>
> 示範快照裡的資料**在其自身時間軸上看起來是新的**，資料齡期可能顯示正常，
> 使用者仍會誤以為是即時資料。
>
> 所以判斷「這是不是示範資料」要看橫幅與 `is_demo` 欄位，**不能從齡期推論**。

# 系統管理

## 日常維運指令

所有指令在專案根目錄執行。**首次建庫與例行擷取的參數不同**，別搞混。

### 資料擷取

```bash
# 先看有哪些來源與狀態
python -m services.ingest.run --list

# 例行擷取（不加 --backfill）
python -m services.ingest.run --source all
python -m services.ingest.run --source celestrak_sw_all

# 首次建庫：回填歷史，ingest_time 依來源發布延遲推算，使 as_of 回放可用
python -m services.ingest.run --source all --backfill

# 預報引擎的訓練資料（OMNI2，六年）
python -m services.ingest.run --source omni2_hourly --years 6

# 封閉網路：只用本地種子檔
python -m services.ingest.run --source all --offline
```

> ⚠️ **`--backfill` 只在首次建庫用。**
> 例行擷取加上它會用推算的 `ingest_time` 覆蓋真實入庫時間，使後續的回放結果失真。
> **建庫一次即可，之後不要再加。**

### 預報與驗證

```bash
# 特徵覆蓋率體檢（先跑這個，確認訓練資料夠不夠）
python -m services.forecast.run --coverage

# 驗證擂台：全 horizon，四折滾動起報
python -m services.forecast.run --verify --splits 4

# 只跑單一 horizon
python -m services.forecast.run --verify --horizon 24

# 以 POD 目標挑操作點；輸出會同時顯示訓練/測試落差
python -m services.forecast.run --verify --objective pod

# 產生最新預報並寫入資料層
python -m services.forecast.run --predict --write
```

### 健康檢查

```bash
python -m pytest tests -q             # 全部契約測試
python -m pytest tests -q -k cssi     # 只跑 CSSI 格式契約
python tools/cssi_compare.py          # STK 驅動檔與來源實檔逐行比對
```

## 產品匯出

### STK / GMAT 驅動檔（CSSI 格式）

```bash
# 標準匯出（觀測 + 來源自帶的預測）
python -m services.exporter.stk_spaceweather --out out/SpaceWeather-All-v1.2.txt

# 只輸出觀測值（回放與驗證用，避免拿預測值當真值）
python -m services.exporter.stk_spaceweather --mode observed_only

# 回放：只用該時刻前已知的資料
python -m services.exporter.stk_spaceweather --as-of 2024-05-10T12:00Z
```

亦可從 API 取得：`GET /v1/exports/stk/spaceweather.txt`。

### 密度修正因子

```bash
python -m services.exporter.drag_correction --start 2024-05-08 --end 2024-05-14
python -m services.exporter.drag_correction --fmt json --out out/drag.json
```

> ### ⚠️ 密度修正因子的適用範圍
>
> 交付值是在**固定參考點 lat 0°／lon 0°** 算出的，**不是全球代表值**。
> 實測顯示評估座標會使倍率變動達 **14.9%**（臺灣位置相對參考點約 **−8.45%**）。
> 對應特定任務區域時必須以該區座標重算：
> `density_ratio(..., lat=25.0, lon=121.0)`。
>
> 此外 `storm_ratio` 是**模型內部的相對比較量**，不是由觀測反演得到的校正係數，
> `calibrated_by_observation` 目前為 `false`。詳見
> [density_model_validation.md](density_model_validation.md)。

### 回放演練

```bash
python tools/e2e_demo.py                                       # 預設 2024-05 Gannon
python tools/e2e_demo.py --start 2022-02-01 --end 2022-02-10   # Starlink 再入
python tools/e2e_demo.py --as-of 2024-05-11T00:00Z             # 無前視偏差回放
```

`--start` 與 `--end` 皆為**含端點**。未給時分秒的日期解為該日 `00:00Z`，
所以 `--end 2022-02-10` 只涵蓋到該日零時；
要涵蓋整日請寫 `--end 2022-02-10T23:59:59Z`。

## 部署

### 本機

```bash
pip install -r requirements.txt
streamlit run apps/dashboard/app.py     # http://localhost:8501
python -m services.api.app              # http://127.0.0.1:5100
```

需要重現文件中的數字時，改用鎖定版本：`pip install -r requirements.lock`
（55 個套件，單一平臺快照，非跨平臺求解結果）。

### Streamlit Cloud

| 欄位 | 值 |
|---|---|
| Repository | `RhynoW/SpaceWeather` |
| Branch | `main` |
| Main file path | `apps/dashboard/app.py` |
| Python version | 3.11 以上 |
| Secrets | 留空（所有資料源皆公開免認證） |

> ### ⛔ 雲端只當展示層
>
> Streamlit Cloud 的容器檔案系統**不持久**、會因閒置休眠，且擷取會佔用同一行程。
> **不要在雲端 app 內執行擷取**——寫入的資料會在重啟後消失。
> 正確作法是以獨立 worker／排程主機執行擷取，寫入持久化儲存，app 只讀。
>
> 日後若接入需認證的來源（Madrigal、Earthdata），憑證一律走平臺 secrets，
> **不得寫入 repository**——本 repo 為公開。

## 疑難排解

| 症狀 | 可能原因 | 處理 |
|---|---|---|
| 儀表板全部顯示無資料 | 尚未擷取，或 `SWX_DATA_DIR` 指錯 | 執行 `--source all --backfill`；用 `/health` 的 `data.root` 確認實際路徑 |
| 頂端出現 DEMO 橫幅 | `data/swx_parquet` 為空，已退回 `data/demo` 示範快照 | 正常行為（雲端展示即如此）。要用真實資料就執行擷取 |
| 某來源擷取失敗 | 端點變更或網路阻擋 | 原始檔已落地於 `data/raw/`，解析錯誤可重跑不需重抓；檢查 `configs/sources.yaml` 的端點 |
| 回放 `--as-of` 查不到資料 | 資料是今天入庫的，語意上當年確實沒有 | 用 `--backfill` 重建可取得性（此為近似，須於報告載明） |
| 新增參數後入庫被拒 | 參數未註冊 | 先在 `configs/params.yaml` 註冊，否則判為 `unregistered_param` |
| CSSI 匯出行數異常 | 日尺度參數被同日較晚的列覆蓋（曾發生過的缺陷） | 跑 `python tools/cssi_compare.py`，用 `--level field` 定位差異欄位 |
| API 回 500 | 未預期例外 | 回應不含內部細節（刻意設計）；詳情看 server log，或以 `SWX_API_DEBUG=true` 啟動 |
| 雲端部署失敗 | Python 版本低於 3.10，或相依安裝逾時 | Advanced settings 選 3.11 以上；`pymsis` 與 `duckdb` 皆有 manylinux wheel，不需編譯 |

### 環境變數（皆可省略）

| 變數 | 預設 | 用途 |
|---|---|---|
| `SWX_DATA_DIR` | `./data` | 資料根目錄 |
| `SWX_CONFIG_DIR` | `./configs` | 設定目錄 |
| `SWX_ROOT` | 自動偵測 | 專案根目錄 |
| `SWX_API_HOST` / `SWX_API_PORT` | `127.0.0.1` / `5100` | API 服務位址 |
| `SWX_API_DEBUG` | `false` | debug 模式（500 回應會附內部細節） |

# 邊界

## 不可用於什麼

**這節比任何功能說明都重要。** 以下是系統明確不做的事，值勤時不得逾越。

> ### ⛔ 禁止事項
>
> - **不得把 24 小時以上的預報用於作業決策。**
>   測試折 BSS 於 24 小時起轉負，訓練折 POD 約 0.83 而測試折僅 0.02–0.38，
>   過擬合落差存在於所有 horizon。
> - **不得把推估值對外表述為實測。**
>   `inference: proxy` 與 `is_proxy=true` 必須隨結論一起傳遞。
> - **不得將 `unavailable` 解讀為 L0。**
>   前者是沒有資料，後者是確認無異常。
> - **未經人工確認的 L3 以上事件卡不得對外發送。**
>   狀態須為 `issued`，非 `draft`。
> - **不得依 DEMO 資料做任何作業判斷。**
> - **不得用地理緯度判斷臺灣的電離層風險。**
>   臺灣地磁緯度僅約 19°N，位於赤道異常駝峰，用地理緯度會系統性低估。

### 系統的非目標

- **不是國家級太空天氣預報中心**，不取代中央氣象署太空天氣作業辦公室。
- **不保證 STK/HPOP 與本系統的密度結果一致**——CSSI 格式已驗證，
  但 STK 端的實際載入與傳播結果尚未交叉比對。
- **不宣稱地磁基準場已與實測驗證**——IGRF 目前只通過值域合理性檢查。
- **不對 GNSS 閃爍風險提供實測判定**——S4／ROTI／TEC 尚無資料源。
- **不產生行動命令**——系統輸出風險等級與建議處置，決策由值勤人員做。

### 目前未校準的項目

以下皆標記為未校準，引用時須一併說明：

| 項目 | 標記 |
|---|---|
| L0–L4 分級門檻 | `calibrated: false` |
| 密度修正因子 | `calibrated_by_observation: false` |
| D-RAP 與在地 HF 通聯的對應關係 | 未校準 |
| 多頻段影響矩陣 | 未校準 |
